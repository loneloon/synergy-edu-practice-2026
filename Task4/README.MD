#### Кейс-задача № 4
Проведите анализ и опишите имеющихся на рынке программного обеспечения информационных систем, построенных по архитектуре WEB-приложений. Оцените и опишите возможности предлагаемых систем по архитектуре WEB-приложений и варианты их использования в компании. Создайте с помощью Delphi 10.2 и MS Internet Information Server (IIS) приложение WEB-архитектуры на любую тему. Базу данных для WEB-приложения создать в MS SQL Server.

#### Ответ
files: server/* client/*


#### Деплой
1. Настроить бд в следующем порядке:
    - ```./server/src/db/setup_db.sql``` для создания БД
    - ```./server/src/db/install.sql``` для создания таблиц
    - ```./server/src/db/fill_db.sql``` для заполнения БД данными (обязательно)
2. Сервер по дефолту слушает порт 8080 на локальной сети.
    - билд серверного приложения располагается в ```/server/build/Win64/*```
    - для корректной работы приложения с MySQL требуется ```libmysql.dll``` в директории из которой запускается сервер, .dll находится в папке с билдом
    - запустить бинарь веб-сервера
    - в консольном интерфейсе ввести команду старт для запуска сервера
3.  Клиент необходимо раздать на порту 80. 
    - ожидаемый порт можно сконфигурировать в веб-сервере в ServerConst1 модуле 
    - некорректный порт клиента приведет к ошибкам CORS
    - билд клиента располагается в ```/client/build/dist/*```
    - также клиентское приложение можно запустить в дебаг режиме через ```yarn start```

#### Комментарий
В рамках задачи написал клиент-серверное web приложение (браузерный клиент).

WebServer реализован через среду разработки Delphi 13.1 - версия, которая была доступна мне по бесплатной лицензии; версия 10.2 упомянутая в задаче, насколько мне известно, выведена из эксплуатации и более не распространяется (по-крайней мере с бесплатной trial лицензией).

О тематике приложения: 
В качестве темы выбрал трекер активностей для логирования собственного распорядка дня и замера времени, затраченного на разнообразную активность в течение дня.

Реализовал серверное приложение по Delphi шаблону с консольным 
интерфейсом. 
Для БД взята MySQL. Соединение и запросы к БД в логике сервера релизованы с помощью библиотеки FireDAC.

WebServer обслуживает следующие руты:
- /user GET : получение данных о юзере
- /user POST : регистрация юзера
- /user/sign-in POST : вход под юзером
- /user/sign-out GET : выход 
- /activity/start POST : начать/создать запись об activity
- /activity/finish POST : завершить activity
- /activity/history GET : история activity за сегодняшний день в локальной таймзоне

Frontend реализован на базе React TS. Основа фронтенда - мой открытый репозиторий с шаблоном и вполне самодостаточной минимальной конфигурацией для сборки и разработки React приложения: https://github.com/loneloon/react-ts-minimal 

UI устроен в виде одностраничного веб-приложения: 
1. При открытии предлагается логин/регистрация. 
2. После регистрации можно залогиниться в приложение
3. Само приложение реализовано в одностраничном формате с удобным мягким скроллом между тремя доступными секциями (нажатия на стрелки в нижней части страницы или точки по правому краю страницы)
4. Первая секция - Info. На ней располагается widget с заметками "Hello", "HowTo" и "Planning advice" с базовыми советами в тематике приложения
5. Вторая секция - Activity Tracker. В виджете можно записать название "занятия" в поле Next Activity и выбрать подходящую группу (или Other, если дефолтные не подходят). 
6. После нажатия кнопки Start (если сообщение с сервером не нарушено), клиент отправит POST запрос на сервер для записи начатой активности. Если запрос выполнен успешно, в верхней панели появится информация по начатому activity и запустится таймер. Если страницу браузера перезагрузить или даже разлогиниться и войти обратно, таймер будет отображать актуальное значение в соответствии с временем начала activity.
7. При нажатии кнопки Finish (если сообщение с сервером не нарушено), клиент отправит POST запрос на сервер для обновления записи об активности временем завершения.
8. Все завершенные активности будут отображаться между панелями "current activity" и "next activity" в виде небольшого scrollable списка завершенных активностей сверхе-вниз от самого недавнего до самого старого (за сегодняшний день по локальной таймзоне).
9. Третья секция - круговой график, кольцо, отображающее процентное соотношение времени, затраченного на разные ГРУППЫ активностей.
